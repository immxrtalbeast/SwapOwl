# Правила бэкенда (Go)

Читают исполнители на Go-тасках и ревьюер. Дополняет `.ai/main-prompt.md`. В жюри есть backend-разработчик на Go: код будут читать, поэтому идиоматичность — часть оценки, а не вкусовщина.

## Язык и стиль

- Версия Go — из `go.mod`. Форматирование `gofmt`, линтер `golangci-lint` с конфигом из репозитория; его предупреждения не подавляются без комментария с причиной.
- Ошибки возвращаются, а не логируются и глотаются. Оборачивание — `fmt.Errorf("...: %w", err)`. Доменные ошибки — экспортируемые переменные (`ErrInsufficientStock`) и проверка через `errors.Is`.
- `context.Context` — первый аргумент у всего, что ходит в БД или сеть.
- Никаких `panic` в обработке запросов. Никакого глобального изменяемого состояния.
- Логи — `log/slog`, структурированные, без персональных данных и секретов.
- Имена — по-английски, короткие, в духе стандартной библиотеки. Комментарии к экспортируемым типам и функциям.

## Домен

- `internal/domain` и `internal/hotoffers` не импортируют `internal/store`, `net/http` и `time.Now`. Время — только через `clock.Clock`, переданный аргументом.
- Количества — `int64` в базовых единицах. Расчёт «сколько порций можно собрать» — целочисленное деление, округление вниз.
- Сортировки в выдаче стабильные: при равном приоритете — по id. Иначе ответ меняется от запуска к запуску и тесты флакают.

## Хранилище и конкурентность

- Протокол блокировок — в `.ai/solution.md`, раздел 2.3, и он обязателен для каждой транзакции, меняющей `batches` (заказ, поставка, «дворник», прыжок времени, сброс): первой блокируются затронутые **продукты** `SELECT … FOR UPDATE` по одному в порядке id, и только потом читаются часы и партии. Блокировка строк партий не используется.
- Создание заказа — одна транзакция: вставить заказ (`ON CONFLICT DO NOTHING`), заблокировать продукты, взять `now`, прочитать партии, построить план чистой функцией домена, списать относительным `UPDATE … WHERE remaining >= $x`, записать движения.
- Приём поставки идемпотентен по id поставки: уникальный индекс и `ON CONFLICT DO NOTHING`, повтор возвращает уже принятую поставку.
- Миграции — в `internal/store/migrations`, только вперёд, каждая в отдельном файле.
- Если таска выбирает другую модель конкурентности (например, один поток для всех изменений склада) — это решение из `solution.md`, а не самодеятельность исполнителя.

## API

- JSON, единый формат ошибки: `{"error": {"code": "...", "message": "...", "details": {...}}}`.
- Отказ заказа при нехватке — `409` с перечнем недостающих продуктов и количеств.
- Вход валидируется до любой записи: отрицательные количества, неизвестные продукты, пустые позиции — `400`.
- События (поставка, заказ, истечение партии, изменение стоп-листа, обновление горячих предложений) — в SSE-поток `/events`.
- У HTTP-сервера заданы таймауты чтения и записи и корректное завершение по сигналу.

## Тесты

- Табличные тесты для доменной логики; property-тесты на последовательности событий для инвариантов.
- Перед каждым коммитом: `go vet ./...` и `go test -race ./...`. Флаг `-race` требует cgo и C-компилятора; если он не работает — это проблема окружения, о ней пишут в таске, а не пропускают флаг.
- Тест проверяет поведение из таски, а не текущую реализацию.
