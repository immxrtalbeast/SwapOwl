# simulator

Генератор поставок и заказов (`internal/generator`) и сравнение алгоритмов горячих предложений.

## bench

    go run ./cmd/simulator bench -seed 1 -n 200 -days 7 [-u 1.5] [-u-extra 1.2,2.0] [-json]

Правило 2.7 (`.ai/solution.md`): пять сценариев (скоропорт в трёх блюдах; избыточная поставка; блюдо с двумя
рисковыми ингредиентами; рисковый продукт с дефицитным попутчиком; дешёвая зелень против дорогого продукта),
модели M1 (множитель `u` на спрос) и M2 (меняется вес выбора), `u_i = 1 + (u − 1) / i` по позиции. Варианты на общих
seed: C0 (без рекомендаций), R, Bg и контроли RND, POP, C1. Основная точка — M2 при `-u`; остальные `u` и модель M1
считаются всегда: по ним проверяется ограничение по отказам и знак.

`simulator.Winner(report)` применяет правило победителя: отказы не больше +1 % заказов к C0 во всех клетках обеих
моделей; в сценарии ничья, если 95 % интервал разности Bg−R включает 0 или разница меньше 5 % списаний C0; победа —
лучше в ≥ 4 сценариях из 5 и не хуже ни в одном. В JSON-отчёте это поле `verdict`; `verdict.analytics` — тело
`GET /api/analytics/bench` (`main_algo`, `waste_reduction_vs_random_pct`, `waste_reduction_vs_nearest_pct`);
`available: false`, если утверждать сравнение нельзя (основным идёт R).

## run — прогон против API по HTTP

Образец внешнего адаптера: симулятор не знает о БД и ядре, только о публичном API.

    go run ./cmd/simulator run -api http://localhost:8080 -key KEY -seed 1 -speed 1 -for 10m

- `-api` — адрес API; `-key` — ключ API (`Authorization: Bearer`), по умолчанию из `SIMULATOR_API_KEY`.
- `-seed` — seed генератора; одинаковый seed даёт те же id поставок и заказов.
- `-speed` — множитель темпа относительно часов стенда (1 — события уходят, когда время стенда доходит до их времени).
- `-for` — длительность в реальном времени; 0 — до Ctrl+C.

Темп берётся из `GET /api/clock`. События превращаются в `POST /api/deliveries` и `POST /api/orders`.
`409 insufficient_stock` — штатный исход, считается как «отклонено». На `5xx` и сетевые ошибки запрос
повторяется с паузой и тем же id (сервер идемпотентен). `401`/`403` останавливают прогон.
В конце печатается сводка.
