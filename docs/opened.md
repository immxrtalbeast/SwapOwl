# Вскрытая упаковка

Срок на упаковке — для закрытой. После вскрытия у продукта свой, более короткий срок (молоко и сливки — 48 ч, соусы — 72 ч, пармезан — 120 ч), и его обязаны маркировать (СанПиН, принципы ХАССП). Сервис моделирует это явно: «Вскрыл» делит партию, и вскрытая часть живёт по сроку после вскрытия.

## Что хранится

- `products.shelf_after_open_hours` — срок после вскрытия, ч (1…87600); `null` — вскрытие срок не меняет. Задаётся в `PUT /api/catalog` (поле `shelf_after_open_hours`; не передано — прежнее значение сохраняется). В сиде демо: молоко 48, сливки 48, пармезан 120, остальные `null`.
- `batches.parent_batch_id` и `batches.opened_at` — у дочерней партии; у обычных партий оба `null` (миграция `0009_opened.sql`). Видны в `GET /api/batches`.
- Движения `transfer_out` и `transfer_in` с причиной `opened`.

## Операция

`POST /api/batches/{id}/open` `{id, qty?, unit?}` (роль `operator`), одна транзакция под протоколом блокировок продукта:

1. `claim` ключа идемпотентности `(open, id)`; повтор с тем же телом — `200`, `replayed: true`, без движений; другое тело — `409 correction_conflict`.
2. Блокировка продукта, чтение времени стенда `now`, затем правила (`domain.PlanOpen`).
3. Из исходной партии уходит `qty` движением `transfer_out` / `opened`.
4. Создаётся дочерняя партия: `quantity = remaining = qty`, `received_at = opened_at = now`, `parent_batch_id`, `expires_at = min(исходный срок, now + shelf_after_open_hours)`. Вскрытие срок только сокращает. Дочерняя партия заводится под служебной поставкой `OPEN-<id>`, срок помечен `confirmed` (рассчитан сервисом, подтверждения при приёмке не требует).
5. Дочерняя партия получает движение `transfer_in` / `opened` на `qty`.

`qty` по умолчанию — одна упаковка (`pack_size` продукта, если у него задан `pack_unit`; но не больше остатка), иначе вся партия.

FEFO не меняется: у дочерней партии ранний срок, поэтому заказ естественно берёт её первой — это и есть поведение кухни.

## Ошибки

| Случай | Ответ |
|---|---|
| партия просрочена, списана или пуста | `409 batch_closed` |
| `qty` больше остатка, не положительное или другой размерности | `400 validation_error` |
| у продукта нет `shelf_after_open_hours` | `400 validation_error`, «вскрытие не меняет срок» |
| неизвестная партия | `404 unknown_batch` |
| `id` уже использован с другим телом | `409 correction_conflict` |

## Баланс движений

Для каждой партии:

```
receipt + transfer_in + return − sale − writeoff − adjustment − transfer_out = remaining
```

- Обычная партия: приход — `receipt`; `transfer_out` уменьшает остаток при вскрытии, `quantity` не меняется. Сохраняется `0 ≤ remaining ≤ quantity`.
- Дочерняя партия: единственный приход — `transfer_in` (ровно `quantity`); дальше продажи, списания и корректировки считаются как обычно.
- По продукту `Σ transfer_in = Σ transfer_out`: вскрытие переносит остаток между партиями, суммарный остаток продукта не меняется (пока обе части непросрочены).
- Остаток продукта по-прежнему равен сумме `remaining` его непросроченных партий.

Сторож инварианта 1 (`tests/invariants`) в этой версии формулу без `transfer_*` проверяет как раньше: добавить в него новый вид движения — отдельная задача человека.
