# Приёмка сканом (FS-137)

Экран «Приёмка» → «Сканировать упаковку». Камера читает DataMatrix «Честного знака» и GS1-128/DataMatrix; из кода берутся GTIN (AI 01), партия (10), производство (11), годен до (17), вес (310n).

## Распознавание
- `BarcodeDetector` — где есть (Chrome на Android), нулевой вес в бандле.
- Иначе `@zxing/browser` 0.1.5 (+ `@zxing/library` 0.21.3, версии зафиксированы), подгружается динамическим `import()` только при открытии камеры. Выбран вместо `zxing-wasm`: чистый JS, без `.wasm`-файла и особой раздачи MIME/CSP, поддерживает DataMatrix. Размер ленивого чанка ≈ 150 КБ gzip (лимит 400).
- Камера требует HTTPS (стенд уже на HTTPS).

## Разбор (`frontend/src/lib/gs1.ts`)
GS-разделитель (0x1D) для переменных AI (10, 21, 91–99…), префикс символики `]d2`, скобочная запись. AI 17 с днём `00` = последний день месяца. Без GS переменное поле читается до максимальной длины AI — на реальных кодах разделитель должен приходить от сканера.

## Сопоставление и отправка
GTIN → продукт хранится в `localStorage` (`gtin-map`) — только удобство одного устройства. Следующий шаг: хранить пары на сервере (GTIN в справочнике продуктов). GTIN примера `04607001234567` заранее привязан к молоку. Количество: вес из 310n (кг) / объём из 315n (л); иначе `pack_size` × 1 скан в базовой единице продукта (молоко — 1000 мл; `pack_size` пока зашит во фронте, API продуктов его не отдаёт); иначе поле пустое, «Принять» неактивна, подсказка «укажите количество». Единица `pack` не отправляется никогда. Сканы копятся в одну накладную, отправка — `POST /api/deliveries` с `expires_on` из AI 17.
